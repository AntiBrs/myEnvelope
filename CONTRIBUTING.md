# Contributing / Közreműködés

## English

1. Fork the repository and create a focused branch.
2. Keep secrets and real financial data out of commits.
3. Copy example environment files locally; never edit them with real values.
4. Add or update tests for behavior changes.
5. Run `pytest` and verify `npx expo export --platform web --output-dir dist`.
6. Keep pull requests small and explain architecture, API, database, and privacy effects.

Commit messages should be concise and action-oriented, for example `Add forecast horizon validation`.

## Magyar

1. Forkold a repót és készíts célzott branchet.
2. Titok és valódi pénzügyi adat nem kerülhet commitba.
3. A példa környezeti fájlokat helyben másold; valódi értéket ne írj beléjük.
4. Viselkedésváltozás mellé készíts vagy módosíts tesztet.
5. Futtasd a `pytest` parancsot és ellenőrizd az Expo web exportot.
6. A pull request legyen kicsi, és térjen ki az architektúra-, API-, adatbázis- és adatvédelmi hatásra.
